## 05:57 · GitHub 同步核对 + MEMORY.md 第二次瘦身

### GitHub 侧结论 [已确认]

```
git ls-remote origin refs/heads/main → 6026f99a9a52141ca44702791b85d69170cd304d
git rev-parse HEAD                   → 6026f99a9a52141ca44702791b85d69170cd304d
git status --short                   → 空
```
**完全同步、无待推送、工作区干净。** 唯一异常是本地追踪引用缺失（`.git/refs/remotes/origin/` 为空 →
`git branch -vv` 显示 `[origin/main: gone]`、`git status -sb` 不带 ahead/behind）—— 属本地元数据缺失，
**不是推送失败**，与 PITFALLS §1 那条一致。

### 新发现：broken ref 会连累 update-ref

拿 `echo probe > .git/refs/remotes/origin/main` 当写入探针时（内容是非法 sha），把它变成了 **broken ref**：
- `git rev-parse` → `warning: ignoring broken ref` + `fatal: ambiguous argument`，**并把 ref 名回显到 stdout**
  （这一行极易被误读成"解析成功"）
- `git update-ref <正确 sha>` → `cannot lock ref ... reference broken`，exit=128
- 删掉坏文件后 update-ref 报 **exit=0 却仍不落盘**（同一现象第二次复现）

最终只有直接写文件才成：`printf '<sha>\n' > .git/refs/remotes/origin/main`
→ `[origin/main]` 恢复、跨调用持久。**教训：补 ref 的内容必须是合法 sha；写坏比没有更糟。**
（另：`git fetch` 打印 `* [new branch] main -> origin/main` 之后 ref 依然不存在 —— fetch 成功 ≠ 追踪引用存在。）
