## 关键实证：演示图八字数据错误

- 演示图 4 出生信息：1981-09-14 08:00，男，湖北
- **实算**（lunar-python）：辛酉 丁酉 **乙未** **庚辰** ｜ 日主 **乙**
- **演示图标注**：辛酉 丁酉 **辛丑** **甲辰** ｜ 日主 **辛金**
- 三条证据链：
  1. lunar-python 实算
  2. JDN 公式 + 偏移 k=49（4 个日期恒定，2000-01-01 戊午日为公认锚点）
  3. 纯规则矛盾：辛日子时戊子 → 辰时应为**壬辰**，图却标甲辰，自身不成立
- **结论：演示图术数数据不可采信**，已写入 AGENTS.md §2.3 作为 RULE-001 的实证佐证

## 关键做法：配色不靠肉眼，从像素实测

- 演示图 1214×1295。色板位于 `y = 105..134`（最宽处 `y ≈ 120`），圆心 x = `731 / 768 / 804 / 840 / 877`
- 对每个圆心取 **9×9 邻域逐通道中位数**（规避抗锯齿边缘）
- 实测结果：`#013A6C` `#DAB37D` `#E5D7C7` `#3C7066` `#B93E35`
- **负向排除**：`y=120` 行还扫到 `x=920..952` 两个灰蓝段（`#8497A0`/`#7F929A`）→ 判定为右侧山水画像素，**不是色板**，剔除
- **有效性验证**：统计界面区（`y=300..1080`）有彩像素，5 色全部命中（3997 / 1577 / 2760 / 7347 / 567 px）→ 色板确为界面实际用色

> 方法论：**色值类数据一律脚本实测 + 双向验证（正向命中 + 负向排除）**，禁止肉眼取色。
