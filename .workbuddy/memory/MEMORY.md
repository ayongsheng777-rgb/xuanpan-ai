# 玄盘AI · 项目长期记忆

## 项目基本盘

- **定位**：**玄盘 AI（XuanPan AI）** —— 罗盘视觉识别 × 确定性术数计算 × AI 解释的移动端 APP。核心不是「AI 算命」，而是**把实体罗盘转成结构化数字数据**（勿与「龙息 · 全息监控引擎」A 股项目混淆）
- **工程核心原则**：AI 负责看 / 理解 / 解释；代码负责算 / 校验 / 映射。**计算层是唯一真源，禁 LLM 介入**
- **技术栈**：已定（2026-09-16）。React Native + Expo / FastAPI / 自研 `packages/fortune-core` / PostgreSQL / Redis / S3-MinIO；历法引擎用 `lunar-python`

## 开发规范（根目录 AGENTS.md 为最高规范）

🔴 **新会话必须先完整阅读 `AGENTS.md`** —— 因为 AI 无跨会话记忆，仓库状态与 git 历史是唯一记忆载体

两条铁律：

1. **每次改动必须创建对应的单独 commit**，一个 commit 一个逻辑单元，禁止攒批提交；禁用 `git add -A`，必须精确暂存
2. **每次改动必须同步测试，交付前测试与验收全部通过**，且交付时必须附上**实际执行的命令 + 真实输出**；未实际运行不得声称「测试通过」

配套约定：

- 提交信息格式 `<type>(<scope>): <中文简述>`，type 用英文（feat/fix/docs/refactor/test/chore/perf）
- 结论必须标注 `[已确认]` / `[推测]` / `[待验证]`
- 交付固定四段：【完成内容】【修改文件】【验证结果】【剩余问题及下一步】
- 引入任何新依赖前，必须先说明：为什么用、有无更轻替代、**成本（是否收费 / 是否需 API key）**、对现有代码影响
