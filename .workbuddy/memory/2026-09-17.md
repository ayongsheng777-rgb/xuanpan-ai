## 踩到并解决的坑（按排查代价排序）

### 1. sdkmanager 下载+解压完成后卡死（两次）
现象：`.temp` 里 zip 已下载完、内容已解压，但目标目录仍为空；
进程 13 分钟只用 24 秒 CPU，缓存零写入 —— 即阻塞在收尾而非计算。
- android-35：解压 7672 个文件后停滞
- NDK 26.1：解压速度仅 **11 文件/秒**，按此估算需 1 小时以上
解法：手动接管 —— 结束 java 进程，用 `C:\Windows\System32\tar.exe`（bsdtar）
把 zip 直接解压到目标目录，再参照同目录已有包的 `package.xml` 补元数据。
效果：286MB 用 **18.6s**，661MB NDK 用 **12.7s**（对比 Java 单线程 10 分钟量级）。

### 2. Gradle wrapper 反复重新解压（与 1 同源）
`gradle-8.10.2-all.zip` 缺 `.ok` 完成标记时，wrapper 每次启动都重新解压 286MB。
前三次构建我都在解压阶段终止了它，标记因此始终没写入 —— 陷入循环，每次白等 10 分钟。
解法：bsdtar 解压 + `touch gradle-8.10.2-all.zip.ok`。

### 3. 中文路径 + JVM 默认 GBK 编码
`settings.gradle` 用 `["node","--print","require.resolve(...)"].execute()` 取路径。
node 输出 UTF-8，而 JVM `file.encoding=GBK` 解码 → 中文路径变乱码 →
报「Included build ... does not exist」，指向一个不存在的目录。
解法：`org.gradle.jvmargs` 加 `-Dfile.encoding=UTF-8`。
（用 `java -XshowSettings:properties` 确认过初始值确实是 GBK。）

### 4. AGP 拒绝非 ASCII 项目路径
报错原文：`Your project path contains non-ASCII characters`。
解法：`android.overridePathCheck=true`。

### 5. Kotlin 版本两处不一致
报错：Compose Compiler 1.5.15 需要 Kotlin 1.9.25，但实际用的是 1.9.24。
根因：`ext.kotlinVersion` 默认 1.9.25（Expo 模板值），而真正驱动编译器的版本
来自 react-native 的 `libs.versions.toml`（1.9.24）—— 两个数字各说各话。
解法：`android.kotlinVersion=1.9.24` 让两者同源。

### 6. JDK 25 不被 Gradle 8.10.2 支持
环境变量 `JAVA_HOME` 指向 Android Studio 自带 jbr（JDK 25），
报错只显示一个版本号 `> 25.0.2`，完全看不出是 JDK 版本问题。
解法：脚本固定用 JDK 17，且**不沿用同名环境变量**。

### 7. Kotlin 独立 daemon 启动失败
报错：`Daemon compilation failed: null` + 一段栈，无任何根因信息。
解法：`kotlin.compiler.execution.strategy=in-process`（在 Gradle daemon 内编译）。

### 8. 构建被沙箱拦截
`:app:processReleaseResources` 失败于写入
`~/.gradle/caches/8.10.2/transforms/...`（"拒绝访问"）。
构建必须读写 Android SDK 与 Gradle 缓存 → 需以正常权限运行。

### 9. app.json 配了 splash 却没给图片

解法：`scripts/gen_app_assets.py` 生成 icon / adaptive-icon / splash，
并补齐 app.json 的 `icon`、`splash.image`、`android.adaptiveIcon`。

## 坑 10：clang / ld.lld 在这台机器上 100% 写不出目标文件（本轮最大障碍）
现象：`error: unable to rename temporary 'x.o.tmp' to output file 'x.o': 'Permission denied'`，
构建卡在**第一个** CMake 任务（`react-native-screens:configureCMake...`）。
根因：**只有「内存映射 + 临时文件重命名」这条写出路径中招**。
- `clang` 走 `FileOutputBuffer`：建 .tmp → mmap 写入 → 解映射 → rename
- `ld.lld` 默认 `--mmap-output-file`：直接 mmap 写输出
解映射到 rename 的毫秒级窗口被文件过滤驱动抢走句柄，rename 缺 `FILE_SHARE_DELETE`
返回 `ACCESS_DENIED`，LLVM 把它统一归类成 `Permission denied`。

逐一证伪的错误方向（这张表比结论更值钱）：
| 假设 | 实验 | 结论 |
|---|---|---|
| 中文路径 | 换纯 ASCII `C:\tmp` 编译 | ❌ 同样失败 |
| 目标格式 / Android target | `clang -E` 只输出文本 | ❌ 同样失败 |
| 沙箱 / 派生方 | Python subprocess、PowerShell 通道各派生一次 | ❌ 同样失败 |
| 文件权限 | 同目录 Python 写+改名、ctypes 直调 `MoveFileExW` 五种 flag | ✅ 全通过 |
| 编译器坏了 | 同目录 MinGW gcc | ✅ 5/5 成功 |
| 杀软信任区没加白 | 火绒信任区**已含** `D:\WorkBuddy`、`D:\Android Studio` | ❌ 仍 100% 复现 |

解法（两个逃生开关，均已实测）：
```
clang --help-hidden → -fno-temp-file          # 直接写目标文件
ld.lld --help       → --no-mmap-output-file   # 不用 mmap 写输出
```
注入点唯一：`<NDK>/build/cmake/android-legacy.toolchain.cmake`
（`ANDROID_COMPILER_FLAGS` / `ANDROID_LINKER_FLAGS` 两个列表）。
环境变量全无效：`CFLAGS`/`CXXFLAGS`/`LDFLAGS` 被 legacy toolchain 清空重建，
`CCC_OVERRIDE_OPTIONS` 在 clang 17 上不生效。

## 第二轮：后端改走域名（oc.ayong.qzz.io）

需求：阿勇要 APP 通过 `http://oc.ayong.qzz.io:8360` 访问后端（该域名由本机 ddns-go 做 IPv6 解析）。

### 事实（[已确认]）

- 域名是 **AAAA-only**（无 A 记录），指向本机「以太网」的 IPv6 隐私地址
- ddns-go 服务：`D:\software\ddns-go\ddns-go.exe`，Windows 服务名 `ddns-go`，
  管理界面 `127.0.0.1:9876`，配置文件 `C:\Users\anyong\.ddns_go_config.yaml`
  （⚠️ 内含 Cloudflare Token 与阿里云 AccessKey 明文，分享日志前必须脱敏）

  | 域名 | 取址网卡 | DNS 服务商 |
  |---|---|---|
  | `oc.ayong.qzz.io` | 以太网 | Cloudflare |
  | `oc.yongshengcloud.asia` | 以太网 2 | 阿里云 |

- 🔴 `oesp.ayong.qzz.io` **不在 ddns-go 管辖内**，是一条陈旧静态记录，指向局域网内
  **另一台设备**（邻居表 MAC `D0-16-F0-01-DE-F4`，那台机没有我们的服务）。
  **阿勇明确要求「不要动 oesp」** —— 已恢复原值，今后勿再触碰。
- Docker 端口映射由 `com.docker.backend` 监听 `::`（双栈）→ IPv6 入站可直达容器

### 坑 12：本机 UDP 53 被代理 TUN 劫持并屏蔽 AAAA

`nslookup` 与 `Resolve-DnsName -Server 223.5.5.5` 查任何 IPv6 域名**一律返回空**，
一度误判为「域名没配」。实际是 sing-tun 接管 DNS 并屏蔽 AAAA（代理防 IPv6 泄漏的常规做法）。
解法：改用 DoH 绕过 ——
`curl -H "accept: application/dns-json" "https://cloudflare-dns.com/dns-query?name=X&type=AAAA"`

### 坑 13：Gradle 不把环境变量算作任务输入 → 复用旧 bundle

只改 `API_BASE_URL` 重跑构建时，`createBundleReleaseJsAndAssets` 被判 UP-TO-DATE，
APK 里嵌的**仍是上一版地址**，而日志一路绿灯（630 up-to-date、1m25s 报 BUILD SUCCESSFUL）。
本轮真实踩中：改域名后构建，APK 内 grep 到的却是 `192.168.57.10`。
解法（已固化进脚本）：把注入值写入 `android/.xuanpan-api-base-url`，变化即清掉
`app/build/generated/assets/createBundleReleaseJsAndAssets/` 强制重打包；
并在结尾读 bundle 内容做断言，失败非零退出。

### 坑 14：Windows 防火墙 RemoteAddress 不接受 `::/0`

`New-NetFirewallRule -RemoteAddress "::/0"` 报「一个或多个地址前缀无效」。
而脚本写成「先删同名规则再建」时，就删掉了阿勇原有的
`Xuanpan API 8360 (IPv6 Public)`（`RemoteAddress=Any`）却建不回来 —— 已按原样恢复。
**改防火墙前先导出原规则**。
