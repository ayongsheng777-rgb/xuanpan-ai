## 关键设计决策

- **每日运程算法**（`fortune_core/daily.py` 模块文档有完整口径）：
  日主 ← 出生日期（只用日柱）；当日干支 ← 复用 `calculate_almanac`；
  日干/日支主气藏干取十神 → 五宫映射（事业←官杀印，财运←财食伤，
  感情←官杀财食伤，健康←印比劫，贵人←比劫食伤印）；
  星级 = 3 + 天干命中 + 地支命中 − 受制，钳制 1..5。
  开运物：生日主之五行 → 幸运色/吉方；干支序号 → 幸运数；该五行地支 → 吉时。
- **时辰未知**：按午时排盘，不影响日主（每日运程唯一输入），tradition 层留痕（RULE-008）。
- **签机动画只是表现层**：签号在按下瞬间由种子唯一确定；help 写明。种子显示可追溯（RULE-001）。
- **个人信息只存本地**：AsyncStorage，不上服务端；看早报时出生日期发给自己的后端，算完即弃。
- **打卡连击**只记本地日期+天数：`markMorningRead`（昨天→+1，否则重计）。

## 追加（同日晚）：传感器采集链路 + 盘面更换 bug 修复

阿勇反馈：原界面不完善，手机传感器采集数据功能没接上，盘面更换操作有 bug。
逐个校验后的结论与修复（3 个独立 commit，都在本地 main 上）：

1. **S1 传感器采集链路断了**（`a4daeb5`）：`/sensors` 能测方位角、能看质量评分，
   但没有任何按钮把读数送进「确认坐向 → 计算 → 测盘档案」链路（V2 §2.1 第 8 步），
   是个死胡同。修复：加「采集当前读数」按钮 → 建会话 → 带 `degree` 参数进
   `/confirm/[sessionId]`（确认页本就支持无识别手动录入）。只传角度不预选坐山
   （RULE-004），无读数时按钮禁用。
2. **D1 盘面更换入口被藏起**（`c4c75f3`）：`/adjust` 的盘式选择器写在
   `{fromTemplate ? ... : null}` 卡片里，从「测盘 → 手动输入」直接进来的用户
   看不到它，换不了盘面。修复：抽成常驻「盘面」卡片；模板卡片只留带出说明。
3. **S2 useSensors 无用 ticker**（`db63731`）：每 200ms 的 setInterval 既不在
   useMemo 依赖里（注释是假话），又在无传感器设备上空转耗电。传感器事件
   10Hz 已驱动渲染，直接删除。行为无变化。

测试：`tests/mobile/test_app_wiring.py` 新增断言 6/7/8（均在旧代码上验证会挂）；
相关 5 个测试文件 75 passed。`tests/mobile` 全量有 2 失败 + 5 错误，
经 worktree 在改动前版本复跑确认是 pre-existing 环境问题
（缺 fastapi/lunar_python 等），与本轮改动无关。
