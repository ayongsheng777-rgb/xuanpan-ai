## 3. 剩余缺口地图（按优先级）

### 3.1 断卦层（六爻 + 八字共用）🟡 高价值

六爻已能「装卦」，但还不会「断卦」——即根据用神旺衰、动爻、变爻给出吉凶结论。
八字已能「排大运」，但还不会「论运」——即大运流年对命局的生克作用。

- **性质**：这层开始涉及流派规则（如用神取用、旺衰权衡），**必须标注不确定性**（RULE-006）
- **难度**：高。不是查表，而是规则引擎（动爻化进、回头生克、合冲刑害的组合判断）
- **建议**：先做「结构化的生克关系提取」（谁生谁、谁克谁、谁合谁冲），再在 TRADITION 层给「参考断语」，
  明确不做「一言定吉凶」的绝对结论

### 3.2 神煞吉凶分级 🟡 中价值

神煞目前「只查不断」（回答有没有、落在哪柱），吉凶分级未做。

- **性质**：神煞吉凶本就流派纷纭（如「羊刃」有吉有凶），不宜做成硬编码吉凶
- **建议**：保留「只查不断」的设计，把吉凶解读交给 AI 层（它读得到 FACT 层的神煞事实）

### 3.3 MCP 暴露层 🟡 高杠杆、低成本

内核已是纯函数，但还没有 MCP Server 暴露层。玄机阁的教训告诉我们：
**192 行 stdio 就能把内核包成 Agent 工具**，但必须修掉它的两个反模式——
只回自然语言摘要（应回 `structuredContent`）、每次调用强行弹浏览器。

- **建议**：加 `@modelcontextprotocol/sdk` 暴露层，返回 `structuredContent`（FACT/TRADITION 已是现成 JSON）
- **性价比**：最高。内核已完成，只差一层壳

### 3.4 康熙笔画字库扩充 🔴 正确性 + 可用性双缺口

实测暴露：**502 字表连「玄」「盘」「阿」「哲」都没有**。行为正确（缺字报错而非造假），
但姓名分析对常见姓名可用性受限。

- **性质**：纯数据工作，瓶颈在数据源（需要可信的康熙笔画表）
- **建议**：扩到 3000+ 常用姓名用字，并补 `verified` 校对标记

### 3.5 三式（奇门遁甲 / 大六壬 / 太乙神数）⚪ 长线

全行业空白，无开源 MCP 项目在做 `[推测]`。价值极高但需先攻克排盘算法，
不是短期能落地的。**建议挂起**，等前几项稳定后再立项。

### 3.6 择日深化（黄历已就绪，缺「择日决策」）🟡 中价值

黄历能「查每日宜忌」，但还不能「择吉日」——即给定事件（嫁娶/开业/动土）反推吉日。

- **建议**：基于 `almanac.py` 的宜忌 + 黄黑道 + 建除，做「吉日筛选」，
  同样标注「属流派规则，仅供参考」
