## 2. 设计 Token —— 配色（实测提取）

色板来源：演示图「设计风格」面板的 5 个色块，**逐像素中位数取样**（坐标 `y=120`，圆心 x = 731/768/804/840/877；方法见附录 A）。

| Token | 色值 | RGB | 语义 | 建议用途 |
|---|---|---|---|---|
| `--brand-primary` | `#013A6C` | 1, 58, 108 | **主色 · 深蓝** | 主按钮、标题、选中态、导航激活 |
| `--brand-gold` | `#DAB37D` | 218, 179, 125 | 金 · 辅色 | 强调描边、勋章、等级、点缀 |
| `--brand-sand` | `#E5D7C7` | 229, 215, 199 | 米 · 底色 | 卡片底、分区背景、留白填充 |
| `--brand-jade` | `#3C7066` | 60, 112, 102 | 墨绿 · 辅色 | 传统纹样、辅助图形、次强调 |
| `--brand-cinnabar` | `#B93E35` | 185, 62, 53 | **朱红 · 强调** | 印章、吉凶提示、关键警示 |

**使用提示** `[推测]`

- `#013A6C` 明度很低（L≈20%），**大色块铺满会显压抑**。建议：大面积用 `--brand-sand`，主色只用于关键元素与文字。
- `--brand-cinnabar` 在传统语境中承载"朱砂/印章"语义，适合做**焦点色**而非普通警示色。
- 五色均经界面采样验证为**实际在用色**（见附录 B），不是摆设色板。

**备选（来源：材料 A §22，本裁定未采用，仅存档）**

`#F5F0E8` `#2C2416` `#C41E1E` `#8B7355` —— 如后续需扩展中性色阶与文本色，可在此基线上派生。

> **落地要求**：以上五色必须固化为 **design token**，禁止在组件内散落硬编码色值（对应 RULE-005 的同源原则：规则不散落）。

## 3. AI 报告结构 —— 三标签

报告页固定三个标签，**顺序不可调换**：

```text
┌───────────────────────────────────────┐
│ AI 解读报告                            │
│                                       │
│ 【盘面事实】【传统分析】【AI 解读】      │
│  ───────                              │
│                                       │
│  坐山   午山                           │
│  向山   子向                           │
│  分金   庚子                           │
│                                       │
│         ✦ AI 解读                      │
│         事业 ──────────                │
│         婚姻 ──────────                │
│         健康 ──────────                │
│                                       │
│      继续追问 AI  ›                    │
└───────────────────────────────────────┘
```

| 标签 | 数据来源 | 可写性 | 对应分层 |
|---|---|---|---|
| **盘面事实** | Fortune Core 确定性计算 | **只读，AI 不可修改** | FACT |
| **传统分析** | 流派规则表 | 只读 | TRADITION |
| **AI 解读** | LLM 基于 `FortuneContext` 生成 | 可生成，**不得回改上述两项** | AI_INTERPRETATION |

**硬性要求**

1. 三个标签的内容在数据层必须**物理分离**，不得合并为同一个字段（这是防 AI 幻觉污染盘面事实的关键机制）。
2. AI 解读内必须包含 `uncertainties`（不确定性标注），用于表达：识别不确定 / 流派差异 / 用户未确认。
3. 报告底部固定附免责声明：`以上内容属于传统文化娱乐/学习参考`。

> **注**：演示图的两标签【简要报告/详细解读】作废；材料 A 的四段结构（【针对你的问题】【参考建议】）并入 **AI 解读** 标签内作为子区块。

## 4. 罗盘扫描页 —— 双入口

**必须同时提供两种输入方式**，二者汇入**同一条识别管线**：

```text
┌───────────────────────────────────────┐
│ ×        罗盘识向                  ⚙  │
│                                       │
│  【拍摄识别】  【相册选择】             │   ← 顶部双 Tab
│  ────────────                         │
│                                       │
│        ┌───────────┐                  │
│        │           │                  │
│        │    ◎      │                  │
│        │  罗盘对齐区 │                  │
│        │           │                  │
│        └───────────┘                  │
│                                       │
│   AI 正在寻找罗盘中心                  │
│   请保持罗盘完整进入识别区域            │
│                                       │
│                ◉                      │
└───────────────────────────────────────┘
```

| 入口 | 来源 | 说明 |
|---|---|---|
| **拍摄识别** | 实时相机 | 引导式拍摄，非普通扫码 UI，定位为「专业测量仪器」 |
| **相册选择** | 系统相册 | 支持已拍摄的罗盘照片 |

### 4.1 统一处理管线（两入口共用）

```text
输入（相机 / 相册）
      ↓
图像质量检测 ──✗──► 提示重拍 / 重选（模糊度、反光）
      ↓ ✓
透视校正 → 圆心/边缘检测 → ROI 裁剪
      ↓
Vision Provider（结构化 JSON）
      ↓
确定性规则校验（坐山≠向山、方位相对性）
      ↓
用户确认页（可手动修正）
```

**硬性要求**

- **无论来自相机还是相册，都必须先过质量检测**。相册里的旧照片同样可能模糊或反光，不得跳过。
- 识别结果必须经**用户确认**方可进入计算（RULE-004）。
- 置信度低或几何关系冲突时，必须显式提示并按 RULE-003 允许返回 `null`。
- 手动修正采用**二十四山环形选择器**，禁止让用户输入角度数值。

### 4.2 识别过程展示

不得显示"AI 正在思考"，必须展示**测量过程**：

```text
✓ 检测罗盘边界
✓ 定位天池
✓ 校正透视
✓ 分析二十四山
● 判断坐山 / 向山
○ 计算分金
```

## 附录 A：配色提取方法与复现

在演示图「设计风格」面板区域定位到 5 个圆形色块：`y = 105..134`（最宽处 `y ≈ 120`），圆心 x = `731 / 768 / 804 / 840 / 877`。

对每个圆心取 **9×9 邻域逐通道中位数**（规避抗锯齿边缘）：

```python
from PIL import Image
from statistics import median

px = Image.open("演示图.png").convert("RGB").load()
Y, centers = 120, [731, 768, 804, 840, 877]
for cx in centers:
    ch = [[px[cx + dx, Y + dy][i] for dy in range(-4, 5) for dx in range(-4, 5)] for i in range(3)]
    print("#%02X%02X%02X" % tuple(int(median(c)) for c in ch))
```

输出：

```text
#013A6C   #DAB37D   #E5D7C7   #3C7066   #B93E35
```
