# 八、模型不要按照品牌设计，而要按照能力设计

这是工程架构的关键。

APP 内部不要写：

```text
if model == GPT
if model == Claude
if model == DeepSeek
```

而应该定义：

```text
Vision Model
Reasoning Model
Fast Chat Model
Embedding Model
Fallback Model
```

例如：

```text
Vision
│
├── OpenAI Vision
├── Claude Vision
├── Gemini Vision
└── 国产 Vision

Reasoning
│
├── OpenAI
├── Claude
├── Gemini
├── DeepSeek
└── Qwen

Fallback
│
└── 国内模型
```

这样未来换模型不用改 APP。

# 十六、中国国内用户访问海外模型的推荐架构

推荐三种模式。

## 模式 A：官方 API Gateway

最推荐的产品化方案。

```text
中国用户
    ↓
玄盘 API
    ↓
AI Gateway
    ↓
海外模型官方 API
```

优点：

- APP 简单
- API Key 不暴露
- 可以统一计费
- 可以切换模型
- 可以自动故障转移
- 可以做日志和成本统计

前提是：**线路、API 使用和服务部署符合当地法律法规以及模型服务商的条款。**

```text

       │      │      │
```

# 三十、最重要的产品原则

整个玄盘 AI 遵循：

```text
             视觉 AI
                ↓
        ┌───────────────┐
        │ 用户确认事实   │
        └───────┬───────┘
                ↓
        ┌───────────────┐
        │ Fortune Core  │
        │ 确定性计算     │
        └───────┬───────┘
                ↓
        ┌───────────────┐
        │ AI Router     │
        └───────┬───────┘
                ↓
      ┌─────────┼─────────┐
      ↓         ↓         ↓
   海外模型   国内模型   私有模型
      └─────────┼─────────┘
                ↓
           AI 解读报告
                ↓
             多轮追问
```

一句话总结：

> **罗盘负责采集，用户负责确认，代码负责计算，模型负责理解，AI Router 负责选择模型，Gateway 负责网络连接。**

这套架构可以让玄盘 AI 后期同时支持 **OpenAI、Claude、Gemini、DeepSeek、通义、智谱以及本地/私有模型**，而不用重新设计 APP。
