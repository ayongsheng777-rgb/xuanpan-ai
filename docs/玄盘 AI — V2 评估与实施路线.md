## 1. 总体判断

V2 规范与项目既有工程原则**高度同源**，不存在方向性冲突：

| V2 原则 | 项目既有对应 | 关系 |
|---|---|---|
| AI 识别/理解/解释，不替代确定性计算（§41.1、§28） | RULE-001 / RULE-002 | 一致 |
| 识别结果必须允许人工修正（§13、§49） | RULE-004 / RULE-008 | 一致，且 V2 加了「原始值不可覆盖」的更强要求 |
| 数据结构化保存，不能只存照片（§10、§11） | RULE-005 同精神 | 一致，V2 更具体 |
| 流派规则模块化 | RULE-006 | 一致 |
| API Key 不进客户端（§22） | 现有架构已是 APP→Backend→Provider | `[已确认]` 一致，无需改 |

**V2 的增量主要在四块**：传感器系统（Phase 2）、罗盘引擎模型化（Phase 1）、
测盘档案实体（Phase 5）、AI 中心（Phase 6）。其中 AI 中心的大部分
（Provider 抽象 / 按能力划分 / Fallback）在方案层已定（AGENTS.md §5），
后端 `services/ai` 已有雏形 `[已确认]`，属于「继续深化」而非「从零开始」。

## 2. 冲突项与裁决

### 冲突 1：底部导航

- **V2 §3 建议**：罗盘 ｜ 测盘 ｜ 分析 ｜ 档案 ｜ 我的
- **基线规范 §1（已裁定方案 A）**：罗盘 ｜ 命盘 ｜ 占测 ｜ 历史 ｜ 我的

**裁决：本轮不动导航。** 理由：

1. V2 §69 自己的执行顺序把「重构底部导航」放在**第 17 条**，
   在 CompassModel / SensorService / MeasurementSession 全部落地之后（Phase 7）；
2. 「测盘」「档案」两个新入口的内容物（Session 实体、罗盘模板库）尚不存在，
   现在改导航会造出两个空壳页 —— 与 sanshi.tsx 注释里「不放占位标签」的既有判断同理；
3. AGENTS.md 规定材料冲突以《产品基线规范》为准，基线未废止前不自行改判。

**待裁决请示**：导航重命名（历史→档案、新增测盘/分析入口）属于产品基线级变更，
留待阿勇在 Phase 5（测盘档案）落地时一并定夺。

### 冲突 2：视觉风格

- **V2 §37 + 演示图**：深色专业仪器风（深藏青底 + 金 + 朱红针）
- **现状**：暖色浅色（#FBF8F3 米白底 + 深蓝主色），五色经基线规范 §2 裁定「勿改」

**裁决：双轨并存，不动既有五色。**

- 既有 `brand` 五色与暖色中性阶**保持原样**（基线规范效力未解除）；
- 新增 `instrument` 深色仪器色域，**只用于罗盘域页面**（罗盘首页 / 手动调节 / 传感器测量）——
  即演示图覆盖的 8 屏所在的域；
- 命盘 / 占测 / 历史 / 我的等页面本轮**保持浅色**，待真机走查两轨并存的效果后，
  由阿勇决定是否全局深色化。

理由：全盘深色化是一次波及所有页面的视觉重做，V2 §18 自己要求「渐进式改造」；
先在仪器属性最强的罗盘域落地深色，风险最小、最贴演示图。

### 冲突 3：隐私表述

- **V2 §54**：「默认本地保存、上传前明确提示」
- **已裁决（2026-09-16）**：隐私表述为「数据可外流」—— 承认照片出端的事实

**裁决：不冲突。** V2 §54 是**产品行为要求**（默认本地、上传前提示），
已裁决项是**文案措辞**（不得承诺「不外流」）。两者可同真：
默认本地处理 + 上传云端识别/AI 前明确提示 + 不承诺数据不出端。无需改文案。

## 5. 风险与注意

- 🔴 **传感器在模拟器上无数据**：expo-sensors 在 Android 模拟器多数返回 null 或恒定值，
  页面必须对「传感器不可用」有一等公民的 UI 态（V2 §63 测试体系也这么要求），
  不能假设数据一定来。
- 🔴 **真机走查缺口继续扩大**：本轮再增 3 个新页面（首页改版 / adjust / sensors），
  全部 `[未验证]` 真机效果。真机走查的优先级进一步升高。
- ⚠️ 磁场强度（μT）仅在真机可得；首页「磁场卡」在后端/仿真模式下显示占位，
  不得编造数值（RULE-008 同精神）。
